**Authoritative System Inventory & Technical Remediation Plan**
**Institution:** DBS Global University (DGU), Dehradun Himalayan Campus
**Date:** October 2026
**Target Release:** Phase 18 — University Demonstration Edition

---

## 1. Executive Summary & Objective

This document provides a comprehensive audit of all student-facing routes, components, navigation items, dashboard widgets, and modal dialogues in Camu-Next. The objective is to standardize the student portal experience for DBS Global University leadership, eliminate static fixtures (`src/data/mockData.ts`), remove simulated success states, connect every supported feature to the authoritative Express 5 / PostgreSQL backend, and document all unsupported institutional backend capabilities honestly.

## 4. Architectural & Security Verification Plan

1. **Session & Cookie Security:** All student API calls use relative `/api` paths with credentials (`include`), avoiding duplicate client instances or `localStorage` auth tokens.
2. **Server-Side Authorization:** Role checks (`STUDENT`) and resource ownership (`studentId === req.user.id`) remain strictly enforced on the Express server.
3. **Data Freshness & Cache Isolation:**
   - On mutation (QR attendance scan, assignment submission, leave request, ticket reply), relevant queries are re-fetched.
   - On logout, local state in `StudentDashboard` and memory stores are reset to `null`.
4. **Finance Integrity:**
   - No payment is displayed as successful without an authoritative `PAID` status in `FeeInvoice` or verified `PaymentReceipt`.
   - Unconfigured payment gateway returns institutional counter instructions with a real `transactionRef`.
